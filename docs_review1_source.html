1. Abstract

Spreadsheets are the most widely used end-user programming environment in the world, yet the language-processing machinery that powers them is rarely examined: every cell formula must be tokenized, parsed, semantically checked, compiled, and — critically — re-evaluated efficiently and in the correct order whenever any cell it depends on changes. This project, Tabula, implements that machinery from scratch as a transparent, fully inspectable system. Each formula (e.g. =SUM(A1:B4)*rate) passes through a complete, hand-written compiler pipeline: lexical analysis, recursive-descent/Pratt parsing into an abstract syntax tree, semantic analysis against a function registry and a named-range symbol table, AST-level optimization (constant folding, algebraic simplification, branch elimination), and code generation to a custom stack-machine bytecode executed by a small evaluation VM with faithful spreadsheet error-value semantics (#DIV/0!, #NAME?, #REF!, #VALUE!, #CYCLE!). Above the per-formula pipeline, a sheet-level engine performs whole-program static analysis: it extracts every formula’s cell dependencies during compilation, maintains a bidirectional dependency graph, detects circular references (reporting the actual cycle path), and performs incremental recomputation — after any edit, only the transitive dependents of the edited cell are re-evaluated, in topological order. An explain command exposes every intermediate artifact of any cell’s compilation, making the system its own teaching tool. The engine is implemented in pure Python with no parser generators or expression libraries, and is validated by unit, scenario, and benchmark tests, including the invariant that incremental results always equal a full recomputation.

2. Problem Statement

A spreadsheet is, computationally, a network of thousands of tiny interdependent programs. Supporting it correctly requires solving a genuinely compiler-shaped problem with two layers:

  1. Per-formula: each formula is source code in a small expression language and must be lexed, parsed, checked for semantic validity (unknown functions, wrong argument counts, invalid references), compiled, and evaluated — with errors contained so that one malformed cell never corrupts the rest of the sheet.
  2. Per-sheet: the collection of formulas induces a dependency graph. The engine must detect circular references, order evaluation so every cell is computed after its inputs, and — because sheets are edited interactively — avoid the naïve strategy of recomputing all N cells on every keystroke, which scales as O(N) per edit and makes large sheets unusable.

No compact, transparent, single-student implementation exists that demonstrates how these two layers work together. Commercial engines (Microsoft Excel, Google Sheets) solve the problem at scale but are closed and internally invisible; textbook compiler projects, conversely, compile one standalone program and never encounter incremental, graph-structured recomputation. The problem addressed by this project is to design and build a complete, observable spreadsheet engine in which both the formula compiler and the dependency-driven incremental recomputation are implemented from first principles and can be inspected at every stage.

3. Motivation

  • Compiler concepts with a visible payoff. Every classical phase — scanning, parsing, symbol tables, semantic checking, IR, optimization, code generation, interpretation — is exercised by a system whose behavior a reviewer can verify instantly by editing a cell and watching exactly the right cells update.
  • Beyond the single-program compiler. Spreadsheet recalculation is one of the few settings where classical compilation meets incremental computation and whole-program dependency analysis: cycle detection is a semantic check over the entire sheet, and topological scheduling decides evaluation order. These are concepts an ordinary course project never reaches.
  • Measurable optimization. The project yields quantitative results required in later reviews: “editing one cell of a 10,000-formula sheet recomputed 14 cells, not 10,000”, and “constant folding removed k bytecode instructions and e dependency edges on the corpus”.
  • Familiarity of the domain. Every evaluator knows Excel. The demonstration requires no explanation of what the system is — attention goes entirely to how it works.

6. Background Study

6.1 Compiler pipeline for expression languages

The classical phase structure — lexical analysis, syntax analysis, semantic analysis, intermediate representation, optimization, code generation, and execution (Aho et al. [1]) — applies directly to formula languages, with the simplification that a formula is a single expression rather than a statement sequence. For parsing, Pratt’s top-down operator-precedence method [2] is the standard technique for expression grammars with many precedence levels and mixed associativity (Tabula has seven tiers, with right-associative ^); it integrates naturally into a hand-written recursive-descent parser and is well documented in modern treatments such as Nystrom [3].

6.2 Spreadsheet implementation technology

Sestoft [4] gives the authoritative account of spreadsheet internals: formulas compiled per cell, a support/dependency graph maintained between cells, evaluation ordered by that graph, and recalculation performed either fully or minimally. Real engines follow the same shape — Excel maintains dependency chains and a “dirty” marking scheme so that recalculation touches only cells downstream of an edit [5]. Circular references are detected as cycles in the dependency graph, and error conditions are represented as first-class error values (#DIV/0!, #NAME?, …) that propagate through arithmetic rather than aborting evaluation — a semantics Tabula reproduces faithfully.

6.3 Graph algorithms

Cycle detection uses depth-first search with the standard three-color scheme (a back edge to a “gray” vertex proves a cycle) [6]; evaluation order uses Kahn’s topological-sorting algorithm [7] restricted to the dirty subgraph. Both are implemented iteratively so that dependency chains thousands of cells deep cannot exhaust Python’s recursion limit.

8. Proposed Methodology

The system is built as two cooperating layers, developed and tested bottom-up across the three course phases.

8.1 Micro layer — the per-formula compiler

Run whenever a cell’s formula is set: lexer → parser → semantic analyzer → AST optimizer → bytecode generator → chunk. The semantic pass simultaneously extracts the formula’s precedent set (all cells and ranges it reads), which is the interface to the macro layer. Optimization runs before final precedent extraction, so a folded branch such as =IF(FALSE, B1, 7) ends with no dependency on B1 — the optimizer visibly changes the dependency graph, not merely execution speed.

8.2 Macro layer — the sheet engine

On every edit: (1) compile the formula through the micro layer; (2) update the dependency graph edges by diffing old and new precedents; (3) run cycle detection from the edited cell, marking any cycle’s members #CYCLE! with the path reported; (4) compute the dirty set as the transitive dependents of the edited cell; (5) re-evaluate only the dirty set, in Kahn topological order; (6) record statistics (cells recomputed vs. total, VM instructions, elapsed time). A full recomputation is the same code path with the dirty set equal to all formula cells — one algorithm, exercised two ways.

8.3 Correctness discipline

Two corpus-wide invariants are enforced by tests from the first phase onward: (i) after any edit script, the incrementally maintained grid equals a from-scratch evaluation of the entire sheet; (ii) enabling or disabling the optimizer never changes any cell value. Error handling follows real-spreadsheet semantics: errors are typed values that propagate through dependent formulas; the engine process itself never crashes on any input.

10.2 Grammar (EBNF)

formula        = "=" expression EOF ;
expression     = comparison ;
comparison     = concat { ( "=" | "<>" | "<" | "<=" | ">" | ">=" ) concat } ;
concat         = additive { "&" additive } ;
additive       = multiplicative { ( "+" | "-" ) multiplicative } ;
multiplicative = power { ( "*" | "/" | "%" ) power } ;
power          = unary [ "^" power ] ;                (* right-associative *)
unary          = "-" unary | primary ;
primary        = NUMBER | STRING | BOOLEAN | range | CELLREF | IDENT
               | IDENT "(" [ args ] ")" | "(" expression ")" ;
range          = CELLREF ":" CELLREF ;
args           = expression { "," expression } ;

10.3 Semantics highlights

  • Types: Number, Text, Boolean, Blank, Error; Range only as an argument to range-accepting functions (=A1:B2 + 1 is a semantic error).
  • Coercions: Blank → 0/"" by context; Boolean → 1/0 numerically; Text never implicitly numeric (="2"+1 ⇒ #VALUE!); & coerces to Text.
  • Error values: #NAME? unknown function/name · #REF! out-of-bounds reference · #VALUE! type error · #DIV/0! division/modulo by zero · #CYCLE! circular reference (path reported). Any error operand makes the result that error; IF evaluates only the taken branch; COUNT, ISNUMBER, ISBLANK follow their per-function policies.

12.2 Representative code — the Pratt parsing loop

Binding powers encode the seven precedence tiers of §10.2; the right-associativity flag is what makes =2^3^2 evaluate as 2^(3^2) = 512 rather than (2^3)^2 = 64.

# tabula/parser.py — binding powers: (left_bp, right_associative)
_BINARY_BP = {
    TokType.EQ:   (10, False), TokType.NE: (10, False),
    TokType.LT:   (10, False), TokType.LE: (10, False),
    TokType.GT:   (10, False), TokType.GE: (10, False),
    TokType.AMP:  (20, False),                                  # & concatenation
    TokType.PLUS: (30, False), TokType.MINUS:   (30, False),
    TokType.STAR: (40, False), TokType.SLASH:   (40, False),
    TokType.PERCENT: (40, False),
    TokType.CARET: (50, True),                                  # ^ right-associative
}

def parse_expression(self, min_bp: int = 0):
    left = self.parse_unary()
    while True:
        tok = self.peek()
        bp = _BINARY_BP.get(tok.type)
        if bp is None or bp[0] < min_bp:
            return left
        self.advance()
        lbp, right_assoc = bp
        next_min = lbp if right_assoc else lbp + 1      # hold bp if right-assoc
        right = self.parse_expression(next_min)
        left = Binary(tok.lexeme, left, right)

 49  def tokenize(text: str) -> list[Token]:
 50      toks: list[Token] = []
 51      i, n = 0, len(text)
 52      while i < n:
 53          ch = text[i]
 54          if ch.isspace():
 55              i += 1
 56              continue
 57          # -- numbers: 12, 3.5, .5  (maximal munch)
 58          if ch.isdigit() or (ch == "." and i + 1 < n and text[i + 1].isdigit()):
 59              start = i
 60              while i < n and text[i].isdigit():
 61                  i += 1
 62              if i < n and text[i] == ".":
 63                  i += 1
 64                  while i < n and text[i].isdigit():
 65                      i += 1
 66              lexeme = text[start:i]
 67              toks.append(Token(TokType.NUMBER, lexeme, float(lexeme), start))
 68              continue
 69          # -- strings: "..." with "" as the escaped quote
 70          if ch == '"':
 71              start, i, parts = i, i + 1, []
 72              while True:
 73                  if i >= n:
 74                      raise LexError("unterminated string literal", start)
 75                  if text[i] == '"':
 76                      if i + 1 < n and text[i + 1] == '"':  # escaped quote
 77                          parts.append('"')
 78                          i += 2
 79                          continue
 80                      i += 1
 81                      break
 82                  parts.append(text[i])
 83                  i += 1
 84              toks.append(Token(TokType.STRING, text[start:i], "".join(parts), start))
 85              continue
 86          # -- references, booleans, identifiers
 87          if ch.isalpha() or ch in "_$":
 88              start = i
 89              while i < n and (text[i].isalnum() or text[i] in "_$."):
 90                  i += 1
 91              word = text[start:i]
 92              ref = CellRef.parse(word)
 93              upper = word.upper()
 94              if ref is not None:
 95                  toks.append(Token(TokType.CELLREF, word, ref, start))
 96              elif upper in ("TRUE", "FALSE"):
 97                  toks.append(Token(TokType.BOOL, word, upper == "TRUE", start))
 98              elif "$" in word:
 99                  raise LexError(f"malformed cell reference '{word}'", start)
100              else:
101                  toks.append(Token(TokType.IDENT, word, upper, start))
102              continue
103          # -- two-char operators before one-char (maximal munch)
104          two = text[i:i + 2]
105          if two == "<>":
106              toks.append(Token(TokType.NE, two, None, i)); i += 2; continue
107          if two == "<=":
108              toks.append(Token(TokType.LE, two, None, i)); i += 2; continue
109          if two == ">=":
110              toks.append(Token(TokType.GE, two, None, i)); i += 2; continue
111          if ch == "<":
112              toks.append(Token(TokType.LT, ch, None, i)); i += 1; continue
113          if ch == ">":
114              toks.append(Token(TokType.GT, ch, None, i)); i += 1; continue
115          if ch in _SINGLE:
116              toks.append(Token(_SINGLE[ch], ch, None, i)); i += 1; continue
117          raise LexError(f"illegal character {ch!r}", i)
118      toks.append(Token(TokType.EOF, "", None, n))
119      return toks

  8  def shape(node):
  9      """Fully parenthesized rendering, so precedence is directly assertable."""
 10      if isinstance(node, Number):
 11          whole = node.value == int(node.value)
 12          return str(int(node.value)) if whole else str(node.value)
 13      if isinstance(node, Text):
 14          return f'"{node.value}"'
 15      if isinstance(node, Bool):
 16          return "TRUE" if node.value else "FALSE"
 17      if isinstance(node, Ref):
 18          return str(node.ref)
 19      if isinstance(node, RangeNode):
 20          return str(node.rng)
 21      if isinstance(node, Unary):
 22          return f"(-{shape(node.operand)})"
 23      if isinstance(node, Binary):
 24          return f"({shape(node.left)} {node.op} {shape(node.right)})"
 25      if isinstance(node, Call):
 26          return f"{node.fname}({', '.join(shape(a) for a in node.args)})"
 27      return repr(node)
